# DSH Launcher 使用指南

适用基线：v0.0.10 源码；当前可下载版本见 [README](../README.md)，开发分支工作区另有未提交改动，行为以当前代码为准。本文说明启动器的使用方式；聊天、Agent 预设和 DSH 原生页面的业务由 DSH 自身提供。下载入口见 [README](../README.md)，开发中的限制见 [TODO](../TODO.md)。

## 安装与首次启动

### 服务商库与实例配置

添加库条目时，可在“快捷选择服务商”中选当前 DSH 运行时目录里的服务商，自动带入名称和 ID；地址、协议和模型默认跟随目录，不必逐项填写。目录中不可配置的条目会显示原因并禁用；也可选“自定义接口”继续手动配置。目录模板未填密钥时使用环境认证，填入后才保存凭据。编辑器的快捷选择、协议和测试模型使用主题下拉组件。

实例页只保留一个“添加服务商”入口，点击后直接选择库中配置；需要新建时切换到“新建配置”。配置说明、模型明细按需展开，服务商库的重命名和删除位于“更多操作”。运行中、共享 Home 与错误提示仍直接显示。

服务商列表在宽窗口显示列表与详情两栏，窄窗口点击条目进入详情，并可返回列表。编辑和预览分阶段展示；预览的变更前后并排显示，长内容在局部滚动区域内查看。直接添加时若实例已应用但模板保存失败，可单独重试保存模板。

“设置 → 服务商库”以左侧搜索列表、右侧详情展示可复用模板。选中模板后点击“应用到实例”，再选择目标、预览并应用；完成后可进入该实例配置。预览和应用期间锁定目标选择，共享 Home 的运行实例会阻止写入。实例页将搜索、从库添加和直接添加集中在工具栏，添加流程与列表分开展示。

在“实例设置 → 模型服务商 → 从服务商库添加”中，选择模板并预览。需要新建或修改模板时点击“管理服务商库”，目标实例会保留；保存模板后自动返回，选中刚保存的条目，再预览并应用。仅编辑库条目不会更新任何实例，取消返回也不会写入实例。

Windows 用户可选择安装版或免安装的 portable.exe。macOS、Linux 包也在 Release 中提供；跨平台构建成功不等于每种系统都已经完成真机验收。

启动器没有预装 Node.js 和 DSH 核心。无需手动安装开发环境：首次启动实例时，启动器检测本机兼容环境，复用可用安装，并联网下载缺少的 Node.js、DSH 和 pnpm。环境下载到启动器的用户数据目录，不是实例 Home。

1. 打开启动器，在首次使用向导中创建实例。
2. 填写名称、Home 路径和 Profile；不确定时为新实例选择独立的空 Home。
3. 创建后点击启动。下载、校验和解压需要等待，网络速度会影响耗时。
4. 准备完成后打开独立实例窗口，在 DSH 原生页面配置服务商并开始使用；也可使用启动器已有的服务商模板导入功能。

安装阶段会显示进度，但解压阶段的总量未知：此时进度条切换为不确定态（不显示百分比），只显示已处理文件数。即使有百分比也不要用它推算剩余时间。没有可用本地环境且离线时，无法完成第一次实例启动。

## Home、Profile 与多实例

| 配置 | 数据关系 | 能否同时运行 |
| --- | --- | --- |
| 不同 Home | 会话、设置和插件数据隔离 | 可以 |
| 相同 Home，不同 Profile | 会话、设置等共享，插件配置分开 | 不可以 |
| 相同 Home，相同 Profile | 数据与插件配置均共享 | 不可以 |

Home 保存会话、凭据、设置等数据，Profile 用于插件配置。修改实例 Home 路径不会搬迁或删除旧数据。要修改实例配置或插件，请先停止该 Home 下的相关实例。

实例窗口相互独立，关闭某个实例不会关闭其他实例。启动器关闭按钮隐藏到托盘；要结束启动器，请使用明确的退出操作。不要把隐藏窗口当作已经停止实例。

| 启动 | 创建、选择、启动和停止实例，进入实例配置 |
| 下载 | 下载插件、插件包、管理已安装插件 |

## 插件

在下载页先核对目标实例。社区目录支持选择来源，插件包按社区给出的顺序逐项安装；手动安装可输入支持的社区命令或每行一个包规格。规格只接受 npm 包名、`github:` 和受信任的 HTTP(S) 压缩包；本地路径（`file:`、`link:`、Windows 反斜杠路径）会被安全策略直接拒绝，重试也不会通过。命令中写的 Profile 会映射到目标实例 Profile，不会因此切换实例。

安装期间可查看日志，插件包显示已完成项数，并提供取消入口。取消需要等待子进程退出；报错后保留错误信息再决定重试。日志复制入口复制界面保留的内容；当前下载页只保留最近 120 行，不应把它视为完整安装记录。

## 模型服务商

实例配置里的"模型服务商"子页展示的是**能看见的真实配置**：当前可识别的路由，加上解析不到或无法确认的引用。插件可以在运行时注册路由，这类路由不会出现在 settings 文件里，所以这个列表是"可识别的配置"，不是"该实例实际在用的全部服务商"。

添加、编辑、移除和从模板应用四条路径都走同一套**先看预览、再点应用**：预览按字段摊开将要发生什么，冲突显示为具体的 `更新` 差异，**点"应用"本身就是对那份预览的确认**——没有需要预先勾选的"全量覆盖"开关。改任一选择会立刻让已有预览失效。若实例配置在此期间被改动（包括你在 DSH 里改），应用会中止并要求重新预览，**不会拿旧预览盖掉新配置**。

密钥有三种明确意图：**保留原密钥**、**替换为新密钥**、**取消引用改走服务商环境认证**。留空不再同时表示前两种，界面上必须选一个。移除服务商只删除设置里那一段，**不删除已存的密钥值**；如果它仍被别处引用（含 `$DSH_HOME/.env`），界面会列出这些引用让你自己决定。

目录型服务商继承 DSH 的目录默认值：只有你显式设置过的字段才会写入，`api` / `baseURL` / `models` 在未设省时省略，因此 DSH 升级目录后你会跟随。想让某条路由不再跟随，需要显式钉住对应字段。写入路由的 ID 之后不可修改；同一服务商再加一个账号，是新建一条不再继承目录的自定义路由。未通过当前运行时核对的目录项只能浏览，界面会说明原因（只有订阅登录认证、没有固定端点、协议不在可手写范围、当前运行时无模型清单）。

模板本身可以在「设置 → 个性化 → 模型服务商模板」里重命名，已保存的密钥会跟着同一条模板走，不需要重新录入。但**这只改模板库**：已经写进各实例的那条路由不会被改写，之后再次应用这条模板才会用新的 ID 写入。

测试连接按模型逐个进行，会真实调用接口并**可能产生用量**；改过端点、协议、模型或密钥后，之前的结果会标记为已失效。它只证明这一个模型在那一刻可访问，不等同于 DSH 已完整校验整份配置。默认模型是 Home 级设置，DSH 对这一段不设校验，请确认模型名真实存在。

回读只交出配置的形状，不交出凭据值；`headers` 这类不属于模板自有字段的项只报名字，写入时原样保留在文档里。不要在问题反馈中附上 API Key 或完整凭据文件。

## 更新运行时

所有实例共享选中的 DSH 运行时。点击「立即更新」后，启动器会先强制退出所有使用当前运行时的受托管实例进程树，确认端口和进程释放后再更新；若任一实例无法停止，更新会中止而不会覆盖仍在使用的运行时文件。启动器管理的运行时由启动器下载和校验；外部 npm/pnpm 安装由对应包管理器更新。无法确认来源或不支持自动更新时，界面给出的是「本次更新已推迟」的警告而不是失败，请用该运行时自己的包管理器更新，不要直接覆盖外部安装目录。

DSH 核心更新和启动器版本更新是两条链路。当前开发分支暂停启动器跟随上游桌面项目的自动更新，获取新启动器请使用本仓库 Release。核心更新不应删除实例 Home 数据。

## 导出与移除

- **仅移除记录**：从启动器列表移除实例，保留文件。
- **删除 Home 并移除**：删除整个 Home，并移除所有共享该 Home 的实例记录，不是只删除某个 Profile。
- 默认删除前询问是否前往导出。选择“前往导出”只跳转，不自动删除；可在个性化设置中关闭该询问。
- 即使启动器里没有正在运行的实例，删除也可能被拒绝：上次启动器崩溃或被强制关闭时，DSH 进程可能仍在后台使用这个 Home。此时先结束该进程（任务管理器/活动监视器中按 Home 路径确认），再重试删除；不要为了绕过提示而手动删目录。

完整 Home 备份可能包含 API Key、会话和设置。备份目标必须位于 Home 外部，请自行保管；不要把完整备份上传到公开问题或聊天中。WebView2 与实例日志的附属清理仍是待实施方案。

## 协作

每个节点绑定一个具体实例。参与同一次运行的实例必须使用不同 Home，并选择本地工作区。

- 自动流水线：依赖完成后才向下游交接产物；失败时保留现场处理。
- 主代理驱动：先分配端口、写入契约，再启动实例并聚焦主实例，由用户继续交互。

工作区会生成 `.dsh-collab.json`、`.dsh-collab-api.md`、`.dsh-collab-agents.md`，不会改写项目原有 `AGENTS.md`。执行期间不要切换或修改当前工作流结构。

## 常见问题

| 现象 | 处理方式 |
| --- | --- |
| 首次准备很慢 | 查看当前阶段和网络；解压阶段显示不确定态进度条，不要据此估计剩余时间 |
| 下载或校验失败后想重试 | 直接再次点击启动即可，安装状态会在失败后自动复位，无需退出启动器或删除 Home |
| 提示 Home 正在使用 | 停止共享该 Home 的实例，或为另一个实例选择独立 Home |
| 修改 Rust 后窗口行为未变化 | 开发场景需重启 Tauri，见开发文档 |
| 插件冲突或服务启动失败 | 保存错误与日志；可使用独立 Home 的修复助手，复制诊断提示词 |

反馈问题时提供启动器/DSH 版本、系统、操作步骤和脱敏错误。不要用手动删除数据目录作为一般重试步骤。
