# 发布检查

本文件是发布操作规范；不代表每次文档或源码修改都需要发布新版本。

1. 检查工作区、分支、远程和暂存内容，明确发布提交。保留无关改动，排除实例数据、诊断截图与临时文件。
2. 按 `bump.config.ts` 同步 package.json、Cargo.toml、Cargo.lock、tauri.conf.json 和两个 README。模拟版本替换，确认 URL 的 tag 与下划线文件名中的版本同时变化。
3. 从确定的版本源码构建。Windows 安装版为 NSIS setup.exe；便携版来自本次 release 构建的 dsh-launcher.exe。仓库继续携带便携版，换版时只暂存明确的旧文件移除与新文件添加，不能把旧 exe 改名充当新构建。
4. 本地发布与 CI 发布明确分工，避免同时覆盖同名资产。CI 使用生成步骤输出的精确路径上传；手动工作流同样不能扫描整个 release 目录选文件。
5. 上传前核对版本、来源提交、文件大小、SHA-256；上传后与 GitHub 返回的资产摘要比对。核对真实资产名（空格可能被转换为点号），验证 README 的安装版和便携版链接能完成 HTTP 跳转且无 404。
6. 验证完整安装包或便携程序能启动；编译成功不等于完成桌面验收。报告未覆盖的平台和手动测试，不声称全部验证。
7. 确认 Release 不含旧版本 exe，tag 指向对应源码。记录提交、标签、资产和验证状态；源码已 push 不能代替资产上传完成。

README 是用户入口，发布未就绪时避免把入口切到尚无资产的版本。更新命名约定时同时调整工作流、版本同步逻辑和中英文 README。
